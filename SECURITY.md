# Security Policy & Threat Model — TableFlow (Vercel / Next.js Stack)

## Threat Model Summary (Phase 1 MVP)

| Asset / Surface | Threat | Mitigations Implemented |
| :--- | :--- | :--- |
| **Table QR Tokens (`/t/:tableToken`)** | Sequential table enumeration; stale QR reuse | 256-bit cryptographically random URL-safe tokens (`crypto.randomBytes(32)`); admin rotation endpoint immediately expires active sessions and revokes prior token |
| **Shared Table Sessions & PIN** | IDOR, eavesdropping, session hijacking across dining guests | Enforced at most ONE active `TableSession` per table (partial unique index `idx_one_active_session_per_table`). First scanner generates a 4-digit PIN; subsequent scanners join via PIN. Protected by `table_pin` rate limiter (5 attempts / 10m). Table status resets to `free` only when 0 active sessions remain. |
| **Guest Orders & Bills** | Cross-table IDOR; price/discount tampering; order flooding | HMAC-signed `httpOnly` `tf_guest_session` cookie; every query scoped strictly to verified server `session.id`; server-side DB pricing/deals/CGST/SGST in integer paise; Upstash Redis rate limiting |
| **Waiter Call Button** | Alert flooding / DoS | 60-second DB cooldown per table session + Upstash rate limiting (`waiter_call` limiter) |
| **Staff & Admin Authentication** | Credential stuffing, brute force, privilege escalation, session theft | NextAuth v5 with `bcryptjs` (cost `12`); RFC 6238 TOTP MFA with hashed single-use recovery codes; 12+ char password policy; last active owner demotion protection; separate per-IP (`login_ip`: 20/15m) and per-email (`login_email`: 5/15m) rate limiters; 5-strike account lockout; atomic `tokenVersion` session invalidation. |
| **Server-Side Route Protection** | Client-side dashboard bypass, visual hydration flash | Server layout guards (`auth()`) on `/admin`, `/chef`, `/kitchen`, and `/staff` enforce server-side authentication and role-based redirects before rendering. |
| **Cookie-Authenticated Mutations** | Cross-Site Request Forgery (CSRF) | Universal `withStaffAuth` wrapper on all mutating routes. Enforces double-submit CSRF cookie (`tf_csrf`) + `X-CSRF-Token` header, blocks cross-site `Sec-Fetch-Site` requests, and verifies `Origin` against `APP_URL`. |
| **Content Security & Headers** | XSS, script injection, clickjacking, cross-origin leaks | Per-request nonce-based `Content-Security-Policy` (disallows `unsafe-inline`, allows `unsafe-eval` only in development); strict `images.remotePatterns` allowlist; `Cross-Origin-Opener-Policy: same-origin`; `Cross-Origin-Resource-Policy: same-origin`; `X-Frame-Options: DENY`; `X-Content-Type-Options: nosniff`; HSTS. |
| **Payments & Refunds (Razorpay)** | Amount tampering, forged callbacks, webhook replay, double capture | Server-side Razorpay order creation; reuses matching open `created` payment; expires stale payments (>15m); rejects concurrent conflicting payments with 409 `PAYMENT_PENDING`. Webhooks verified via `crypto.timingSafeEqual` HMAC-SHA256 with stored payment amount & currency validation and conditional idempotent updates (`status != 'captured'`). Only confirmed orders count toward payable bills. Equal bill split distributes remainder paise to exact sum. Manager refunds and waiter order voids supported. |
| **Realtime Privacy (Supabase)** | Channel guessing, eavesdropping, client-side spoofing | Cryptographically unguessable HMAC-derived channels per session (`session_private_${sessionId}_${token}`) and per staff role (`role_private_${role}_${token}`). Guests only receive their own channel; staff channels gated via authenticated `/api/staff/realtime-channel`. Client broadcasting blocked (`broadcast: { self: false }`). Broadcast payloads sanitized to strip staff personal names and emails. Jittered fallback polling (20s base +/- 25% jitter) triggers only when connection is down. |
| **Abuse Controls & Limits** | Promo code exploitation, order spam, process snooping | Atomically enforced deal rules (`isOneTime`, `maxRedemptions`, `perSessionLimit`, `perTableLimit`) inside order transaction. Per-session caps: max 5 open orders in progress, max 30 items per order, max ₹20,000 order value without prior staff verification. `/api/health` rate-limited with process uptime dropped from public response. Short `stale-while-revalidate` Cache-Control on `/api/guest/menu`. |
| **Inventory & Availability Engine** | Float rounding errors, ghost dish ordering, stock drift | Money stored strictly in integer paise; purchases accept rupees but reject amounts rounding to 0 paise. Dish availability evaluated server-side. Ingredient availability sync runs inside the same database transaction as stock status updates to prevent drift. Immutable `stock_events` and audit logs. |
| **Secrets & Code Hygiene** | Secret leaks, unpinned dependency attacks | Strict fail-fast Zod startup validation (`src/lib/env.ts`); all dependencies pinned in `package.json` without `^`; zero high/critical vulnerabilities via `npm audit`; pre-commit secret scanning on every commit. |

## Reporting a Vulnerability

Please **do not** open a public GitHub issue for security vulnerabilities. Contact the repository maintainer privately or submit a GitHub Private Security Advisory with reproduction steps and impact details.
